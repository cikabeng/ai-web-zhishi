# 开发计划（21 天基线 · 单人）

> 前置：`00-环境勘察报告.md` 的缺口已补（Git 必装）。
> 节奏假设：每天 4–6 小时有效开发；每周留半天缓冲用于还债（补文档、修评测回归）。
> **所有日期为相对天数 D1–D21**，因为你还没给截止时间；确定后我把 D 映射成真实日期。

---

## 0. 里程碑总览

| 里程碑 | 天数 | 主题 | 一句话验收 |
|---|---|---|---|
| **M0** | D1 | 环境与骨架 | 前后端能跑起来，仓库有第一批真实提交 |
| **M1** | D2–D5 | 语料与入库 | 一键 ingest 20 篇，检索调试页 top5 肉眼合理 |
| **M2** | D6–D9 | 问答闭环 | 带引用的流式问答可用，无覆盖能拒答 |
| **M3** | D10–D13 | 教学策略层 | 三级阶梯可演示，索要完整代码的泄露率 ≤10% |
| **M4** | D14–D17 | 教师端与评测 | 一键跑评测出 6 项指标，页面可见趋势 |
| **M5** | D18–D21 | 交付 | 新机器 30 分钟跑通；视频 5–8 分钟 1080p |

> 若只剩 10 天：M0+M1 压到 2 天、M2 用 3 天、M3 用 2 天、M4 用 2 天、M5 用 1 天；**P2 全部砍掉**，评测集缩到 40 条。

## M0 · 环境与骨架（D1）

- [ ] `winget install --id Git.Git -e`，装完 `git --version` 验证；配置 `user.name` / `user.email`
- [ ] `git init`，提交 `.gitignore`（Python + Node + 运行时 storage/）
- [ ] `python -m venv .venv`（放在 `backend/` 下），建 `requirements.txt` 初版
- [ ] 后端骨架：`main.py` + `/api/health` + `config.py`（pydantic-settings）
- [ ] 前端骨架：`npm create vite@latest frontend -- --template vue-ts`，装 Element Plus + Pinia + Router，配 `/api` 代理
- [ ] `scripts/dev.ps1` 一键起前后端
- [ ] `README.md` 初版（项目简介 + 架构图占位 + 运行方式 + 目录说明）
- [ ] `backend/.env.example`（按架构文档 §11）
- [ ] `docs/devlog.md` 开始记录（每天一条，是"真实开发过程"的证据）

**验收**：`dev.ps1` 起两个进程，浏览器 5173 打开是骨架页，`/api/health` 返回 200，`git log` 有 ≥3 次语义化提交。

**提交示例**：`chore: init repo & gitignore` / `feat(backend): fastapi skeleton with health check` / `feat(frontend): vue3 + element plus bootstrap`

## M1 · 语料与入库（D2–D5）

- [ ] **语料准备**（最容易被低估，先做）：20 篇实验指导/讲义/FAQ，格式 PDF/DOCX/MD 混合
- [ ] loaders：pdf（PyMuPDF，含页码）、docx、md、txt
- [ ] `normalize.py`：去页眉页脚、合并断行、全角半角统一
- [ ] `chunker.py`：heading 边界 + 代码块保护 + 450 字/80 重叠（**这是最该写单测的模块**）
- [ ] `embedder.py`：`api` / `hash`（离线确定性）两种实现，同一接口
- [ ] `vector_store.py`：Qdrant 本地模式，payload 含全部元数据
- [ ] `bm25.py`：jieba 分词 + 英文标识符保留，索引持久化到 `storage/bm25/`
- [ ] `pipeline.py`：单文件 / 整目录入库，状态机 + 失败原因
- [ ] `scripts/ingest.py` CLI
- [ ] 检索调试接口：`/api/admin/search?q=` 返回 dense / bm25 / 融合 / 重排四段结果与分数（**答辩时这就是"技术亮点"的现场证据**）

**验收**：20 篇全部 `indexed`；对 10 个预设问题，top5 中包含人工标注的正确 chunk ≥ 7 个；50 页 PDF 入库 < 20 s。

## 1. Git 工作流（比赛明确要求"真实开发过程"）

- 分支：`main`（可运行） + `feat/xxx` / `fix/xxx` / `docs/xxx`，合并用 `--no-ff` 保留轨迹
- 提交信息：Conventional Commits（`feat|fix|docs|refactor|test|chore(scope): 描述`）
- **每天至少 2 次提交**，禁止"最后一天一次性 push"
- 每完成一个里程碑打 tag：`v0.1-m0` … `v1.0.0`
- 用 Issue 记录任务（哪怕只有你一个人），PR 描述里写"改了什么/为什么/怎么验证"
- `docs/devlog.md` 每天一条：今天做了什么、卡在哪、明天做什么

> 这套流程本身就是评分点：评委看到的是 60+ 次有意义的提交 + issue + PR，而不是一次"Initial commit"。

## 4. 视频分镜（5–8 分钟）

| 时间 | 画面 | 要点 |
|---|---|---|
| 0:00–0:40 | 痛点：学生把作业贴给 AI、复制答案、报错看不懂 | 一句真实场景，不要空话 |
| 0:40–1:20 | 方案总览 + 赛道定位 | 本地知识库 + 教学校验，一句话讲清差异 |
| 1:20–2:30 | **演示1**：上传报错截图 → 原因排序 + 验证步骤 | 强调"不给代码，给排错思路" |
| 2:30–3:40 | **演示2**：问"直接给我完整代码" → 拒绝 + L1 提示；提交尝试 → L2；答题 → L3 骨架 | 全场最重要的 70 秒 |
| 3:40–4:40 | **演示3**：概念问答 → 点引用卡片跳到原文页码 | 证明不靠幻觉 |
| 4:40–5:40 | 技术亮点：检索调试页 dense/BM25/融合/重排 四段对比；拒答阈值 | 用界面讲技术，不念 PPT |
| 5:40–6:40 | 教师端：文档管理 / 未覆盖问题池 / 评测看板指标趋势 | 数据飞轮 |
| 6:40–7:30 | 架构图 + 工程规范（Git 历史、`.env`、测试、CI） | 证明是工程而非玩具 |
| 7:30–8:00 | 价值与展望（可推广到其他课程） | 收尾 |

录制要点：固定演示问题、固定语料、先预演 3 次；关键片段分段录再剪，避免长镜头翻车。

## 5. 风险与缓冲

| 风险 | 触发信号 | 应对 |
|---|---|---|
| 范围失控 | 想加"在线判题""多模态视频" | 一律进 P2，写进 Roadmap 而不是代码 |
| 语料不足 | D3 还没凑够 15 篇 | 先用自己的实验报告 + 课程 PPT 转文本，宁少勿滥 |
| API 不稳定/限流 | 首 token 经常 > 3 s | 加超时重试 + 结果缓存（同问题 10 分钟内复用） |
| 策略层被绕过 | 学生换说法就出完整代码 | 评测集专门放 10 种绕法，泄露率作为回归门槛 |
| 时间不够 | D15 还没到 M3 | 砍 M4 的学情统计与 CI，保 M3+M5 |
| 视频赶工 | D19 还没脚本 | D16 先把脚本和演示数据准备好，录制只做"执行" |

**缓冲**：D21 本身是缓冲日，不排新功能。

## 6. 需要你拍板的 6 件事（阻塞项）

1. **截止日期**（决定 21 天还是 10 天方案）
2. **团队人数与分工**（决定要不要并行前端/文档）
3. **模型 API**：用哪家、Key 什么时候能给（**M2 起硬依赖**）
4. **语料**：能否提供 15–20 份真实实验文档（PDF/DOCX）
5. **是否需要公网在线 Demo**（把部署从 M5 提前到 M4）
6. **报名赛道**：是否确认"赛道 2 主报 + 5/9 叙事"的写法

你确认后，我按 M0 开始动手：先装 Git、建仓、起骨架，每一步都会给你看结果再继续。
