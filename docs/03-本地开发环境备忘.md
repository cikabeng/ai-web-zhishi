## 2. 三条必须知道的"配方"

这台机器的沙箱对三类操作有限制，实测结论如下（都是"放开权限 + 改临时目录"能解决，不需要改代码）。

### 2.1 安装 Python 依赖

```powershell
# 需要放开权限；临时目录必须在工作区内；用国内镜像
$env:TEMP = 'E:\ai web project\.tmp'; $env:TMP = $env:TEMP
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt `
    --no-cache-dir --progress-bar off `
    -i https://pypi.tuna.tsinghua.edu.cn/simple
```

- 沙箱内直接装会失败：`ensurepip` 返回 1、或 `Errno 13 Permission denied` 读写临时文件。
- 默认 PyPI 会长时间空转（实测 CPU 空烧 10 分钟无进展），**必须用镜像**。

### 2.2 安装前端依赖

```powershell
cd frontend
npm install --cache .npm-cache --no-audit --no-fund
```

- 沙箱内会报 `EPERM spawn`：npm 的安装脚本以管道方式启动子进程，被系统拒绝。
- 缓存目录放到项目内，避免写 C 盘用户目录。

### 2.3 构建 / 启动前端

```powershell
$env:TEMP = 'E:\ai web project\frontend\.tmp'; $env:TMP = $env:TEMP
cd frontend
npx vue-tsc --noEmit   # 类型检查，无需放开权限
npx vite build         # 需要放开权限
npx vite --port 5173   # 需要放开权限
```

- `vite` 依赖 esbuild 的管道式子进程：沙箱内报 `spawn EPERM`。
- esbuild 会把临时文件写到 `%TEMP%`，若指向 C 盘会在删除时报 `Access is denied`，所以要把 `TEMP` 指到项目内。

> 直接用普通终端（非沙箱）运行时，以上限制都不存在，`npm run dev` / `uvicorn` 直接可用。

## 3. 日常命令

```powershell
# 一键起前后端（各自新开窗口）
.\scripts\dev.ps1

# 后端测试
cd backend; ..\.venv\Scripts\python.exe -m pytest -q

# 后端单独启动
cd backend; ..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000

# 前端构建检查
cd frontend; npm run build
```

健康检查：<http://127.0.0.1:8000/api/health>　接口文档：<http://127.0.0.1:8000/api/docs>

## 4. 常见错误对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `ensurepip ... returned non-zero exit status 1` | 沙箱拒绝写临时目录 | 放开权限创建 venv，或改 `TEMP` 到项目内 |
| `Errno 13 Permission denied ...pip-unpack-*.whl` | 同上 | 同上 |
| pip 长时间无输出、CPU 空转 | 直连 PyPI 解析/重试卡死 | 换清华镜像 |
| `npm error code EPERM / syscall spawn` | 沙箱禁止管道式子进程 | 放开权限重跑 |
| `esbuild ... spawn EPERM` | 同上 | 同上 |
| `esbuild ... remove C:\...\Temp\esbuild-xxx: Access is denied` | 临时目录不可删 | `$env:TEMP` 指向项目内 |
| uvicorn 日志中文乱码 | 控制台编码 | 设置 `PYTHONUTF8=1`（`dev.ps1` 已内置） |
