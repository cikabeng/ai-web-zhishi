## 段 1｜项目介绍（0:00–0:40）

**画面**：项目首页（`http://localhost:5173`），停留 3 秒；切到 README 封面段落。

**讲稿**：
> 大家好，我们是广东工商职业技术大学计算机学院的团队，作品是「知实 AI」——一个面向高校软件工程实训的 RAG 智能答疑知识库。
>
> 学生遇到报错时，通常把代码交给通用 AI 然后复制答案，结果是作业做完了、知识没学会，而且 AI 还会编造并不存在的函数。我们的做法不一样：**通用 AI 帮你抄作业，我们做的是拒绝给答案、只给可溯源提示的 AI**。
>
> 系统有三条底线：每条结论都能点开引用核对原文；资料里没有就明确说没有；默认不给你能直接提交的完整实现，而是用四级提示引导你自己改出来。

**字幕重点**：拒绝给答案 · 只给可溯源提示

## 段 2｜知识库与检索（0:40–1:35）

**画面**：知识库页 → 点开「分块预览」→ 切到 `/api/health`。

**操作**：
1. 展示文档列表：4 篇文档、15 个片段，状态均为 `indexed`
2. 点开任一文档的分块预览，停留 3 秒
3. 切到 `http://127.0.0.1:8000/api/health`，指一下 `documents: 4`、`chunks: 15`

**讲稿**：
> 系统支持 PDF、Word、TXT、Markdown 上传，自动解析、分块、去重、建立索引。每份资料按内容做哈希去重，删除文档会同步清理向量，不会出现「删了还能搜到」。
>
> 检索用的是混合打分：75% 的向量相似加 25% 的字面覆盖。向量是本地哈希生成的 512 维表示——不需要 GPU、不需要外网、不需要任何 Key，所以评委 clone 之后零配置也能跑完整链路。知识库检索不到时，会回落到内置的示例资料，保证演示不会空场。

**字幕重点**：4 篇文档 / 15 片段 · 混合检索 0.75 + 0.25

## 段 3｜L1→L4 逐级引导 + 引用核对（1:35–3:15）

**画面**：教学页 `http://localhost:5173/teaching?demo=1`，自动载入演示问题。

**操作**：
1. 展示分类结果「编程报错」与置信度 0.95
2. 点击 L1，展开引用卡片 → **点开一条引用，滚动到原文对应段落**
3. 点「继续」到 L2 → L3 → L4（注意 L3 前会弹提交框，见段 4）
4. 切到命令行或 `/api/teaching/hint` 展示 `llm_status: "model"`

**讲稿**：
> 这是核心的分层教学页。系统先把问题分成六类之一，这里是「编程报错」，置信度 0.95，也可以手动改。
>
> 现在点 L1，得到的是知识点提示——注意每条结论后面都有引用编号。我点开引用，能看到它来自哪份文档、第几段，以及原文片段。这不是模型编的，是从资料里真实检索出来的。
>
> 继续到 L2 是解题思路，L3 是局部示例。请注意：**每页最多推进一级**，而且示例里的代码不超过六行，系统不会给你一份能直接交的完整实现。
>
> 到 L4 是相似例题，来自固定题库并明确标注 AI 生成，用于迁移练习。

**字幕重点**：L1 知识点 → L2 思路 → L3 局部示例 → L4 相似例题；引用可点开核对

## 段 4｜L3 提交门槛与无据拒答（3:15–4:10）

**画面**：教学页，先触发 L3 提交弹窗；再在输入框换一个知识库外的问题。

**操作**：
1. 从 L2 直接点 L3 → 弹出「请先提交你的思路或代码片段」→ 展示后关闭
2. 输入：`请讲解量子退火算法在我校食堂排队优化中的应用，并给出完整代码`
3. 展示回答开头「资料不足」与拒绝给代码的表述，展开覆盖度徽章

**讲稿**：
> 这一页体现我们的产品立场。引导模式下，想看 L3 局部示例，必须**先写下自己的尝试**——系统不是不想帮，而是要先让思考发生。
>
> 再看一个反面例子。我问一个知识库外的问题：量子退火优化食堂排队，还要完整代码。系统明确回答「资料不足」，并说明现有资料只覆盖 Python 报错和 Web 调试，不提供任何代码。
>
> 对于资料没覆盖但很常见的 Python 错误，我们还有一层通用知识：给出排查思路，但界面明确标注「通用 Python 知识，非课程资料」。既不装作有据，也不只是说我不知道。

**字幕重点**：L3 需先提交尝试 · 无据明确拒答 · 通用知识明确标注

## 段 5｜截图报错分析（4:10–5:00）

**画面**：报错分析页 `http://localhost:5173/errors?demo=1`。

**操作**：
1. 展示示例截图上传 → OCR 识别结果
2. 手动改一个识别错的字 → 点「重新分析」
3. 展示分析结论与引用

**讲稿**：
> 学生实际遇到的往往是一张报错截图。这里上传截图后，系统会先做图片校验，再走 OCR 识别。默认用本地离线 OCR，配了视觉模型也可以走模型通道。
>
> OCR 结果**可以手动修改**——因为识别错一个变量名，后面的检索就会全错。改完点重新分析，会复用同一套检索和教学引擎，所以同样有引用、有护栏。

**字幕重点**：截图 → OCR → 可编辑 → 复用检索

## 段 6｜AI 技术亮点（5:00–5:55）★ 官方明确要求

**画面**：① 架构图（技术文档 PDF 第 3 章截图，或用 PPT 第 4 页）→ ② `/api/health` 页面 → ③ 教学页右下角模型状态。

**讲稿（这段最能体现技术深度，不要跳过）**：
> 最后讲 AI 是怎么集成的。我们不依赖 LangChain，自己写了整条链路：问题进来先分类，再检索，构建引用，判断证据覆盖度，生成分层提示，经过安全护栏，最后才交给模型润色。
>
> 模型只做一件事：**润色 L1 到 L3 的讲解**。L4 固定题库不交给模型。传给模型的内容只包含被引用到的资料片段，输出里的引用编号还会再清洗一次，越界编号直接剔除——这既省 token，也防止模型编造引用。
>
> 现在是真实模型在运行：健康检查里 `demo_mode` 是 false、`llm_configured` 是 true；刚才那次请求 `llm_status` 是 `model`，说明提示确实由模型生成。模型失败会自动回退模板，并在页面标注，绝不把模板伪装成 AI。
>
> 现场如果 API 挂了，把 `DEMO_MODE` 改成 `on` 重启就行，检索和引用完全不受影响。

**字幕重点**：自研 RAG 链路 · 仅传被引用片段 · 引用编号清洗 · model/template/fallback 三态标注
