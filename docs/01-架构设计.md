# 架构设计：智答实训（RAG 知识问答系统）

> 作品名暂定：**智答实训 · 高校软件工程实训智能答疑知识库**
> 主报赛道：**2 - RAG 知识问答系统**；叙事上兼顾 **5 - AI 教育与学习平台**、**9 - AI 安全与内容治理**（"负责任 AI"）。
> 设计原则：**少即是多**。一个人能维护的模块才保留；每个模块必须能出现在演示视频或评分表里。

---

## 1. 目标与非目标

### 目标（按优先级）

1. **答得准**：只依据本地课程知识库回答，每条结论可点击溯源到文档 + 页码。
2. **不乱答**：检索无覆盖时明确拒答，而不是生成看似合理的错误代码。
3. **教思维**：识别"直接要答案"的请求，走三级提示阶梯（提示 → 思路 → 骨架），不产出可直接提交的完整实现。
4. **能自证**：内置评测集，页面可见"检索命中率 / 忠实度 / 答案泄露率"三项指标。

### 非目标（明确不做，避免范围失控）

- 不做在线代码运行/判题（沙箱复现列为 P2，不上主线路）
- 不做多租户、不做移动端 App、不做微服务拆分
- 不做模型微调（评测数据量不够，收益低）
- 不做视频/音频多模态，只做"图片（报错截图）→ 文本"

## 3. 两条核心数据流

### 3.1 入库流（教师上传 → 可检索）

```
上传文件 → 校验(类型/大小/去重sha256) → 解析(按类型选 loader)
   → 归一化(去页眉页脚/合并断行/中文标点)
   → 结构化切分(heading 边界 + 代码块保护)
   → 生成元数据(course/doc_type/chapter/page/breadcrumb/has_code)
   → 向量化(batch, 失败重试) → 写入 Qdrant(带 payload)
   → 写 SQLite(documents/chunks 状态机: pending→indexed/failed)
   → 重建 BM25 内存索引(启动时加载, 增量更新)
```

状态机很重要：`failed` 的文档要在教师端显示原因，而不是静默失败——这是演示时"工程严谨性"的体现。

### 3.2 问答流（学生提问 → 带引用的回答 → 反馈）

```
用户问题(+可选截图)
  → ① 预处理: 多轮改写(最近3轮) + 归一化 + 关键词抽取(jieba+英文标识符+报错码)
  → ② 意图分流(LLM结构化输出): concept | debug | request_solution | chitchat
        + 槽位: course, error_text, code_snippet, requested_level
  → ③ 检索: dense(top30) + BM25(top30) → RRF融合 → rerank → top 5~6
        + 过滤: course / doc_type
  → ④ 覆盖度判定: 低于阈值 → 拒答分支(明确说没有 + 给替代路径)
  → ⑤ 策略生成(按意图选模板, 输出结构化 JSON)
  → ⑥ 泄露检测: 命中"完整实现"特征 → 降级重写 + 记事件
  → ⑦ 引用校验: 答案中的 [n] 必须存在对应 chunk, 否则剔除该句
  → ⑧ SSE 流式返回 → 落库(messages/feedback/eval样本)
```

第 ⑤ 步输出**结构化 JSON 再由前端渲染**，而不是直接吐 Markdown：只有结构化才能做阶梯解锁、引用卡片、泄露检测这些交互。这是与"套壳聊天"最本质的区别。

## 4. 技术选型决策

| 决策点 | 选择 | 理由 | 放弃的方案 |
|---|---|---|---|
| 后端框架 | FastAPI + Uvicorn | 原生 async + SSE 友好 + 自动 OpenAPI（答辩可直接展示 /docs） | Flask（同步、SSE 别扭）、Django（重） |
| 前端 | Vue 3 + Vite + TS + Pinia + Element Plus | 你熟悉 Vue；Element Plus 组件全，省 UI 时间 | React（学习成本）、Nuxt（不需要 SSR） |
| 向量库 | **Qdrant 本地嵌入式**（`QdrantClient(path=...)`） | 无 Docker 也能跑；API 与服务端一致，日后可迁移 | Milvus（重）、Chroma（能力弱）、pgvector（要装 PG） |
| 关键词检索 | `rank_bm25` 内存索引 | 零依赖、可实现、可解释；对报错码/API 名有效 | Elasticsearch（要 Docker，过重） |
| 融合 | RRF（Reciprocal Rank Fusion, k=60） | 不需要分数归一化，工程上最稳 | 加权求和（要调权重，脆弱） |
| 重排 | API `bge-reranker-v2-m3`（无 key 时降级为不重排） | 显著提升 top5 精度，且无需 GPU | 本地 cross-encoder（torch 风险） |
| Embedding | API `bge-m3`（1024 维），本地/哈希为降级 | 免 torch；中文技术文档效果好 | 纯本地（体积/兼容风险） |
| 业务库 | SQLite + SQLAlchemy 2.0 | 零运维，评审一条命令就能跑 | MySQL/Postgres（要装服务） |
| 鉴权 | JWT（Bearer）+ 角色 `student/teacher` | 简单、无状态、够用 | Session（跨域麻烦） |
| 文档解析 | PyMuPDF(pdf) / python-docx(docx) / markdown-it(md) | 成熟、纯 Python、cp313 有轮子 | unstructured（依赖重） |
| 截图识别 | VLM API 优先，`rapidocr-onnxruntime` 兜底 | 轻量、无需 torch | PaddleOCR（依赖重） |
| 流式 | SSE（`text/event-stream`） | 比 WebSocket 简单，够用 | WebSocket |

## 7. 检索层设计（技术亮点之一）

### 7.1 切分策略

- 以 **heading 为一级边界**，形成 section，并保留 `breadcrumb`（如 `Python实训 > 第3章 函数 > 3.2 作用域`）。
- section 过长时按段落贪心聚合到 **约 450 字**，重叠 **80 字**。
- **代码块永不切断**；超过 800 字符的代码块单独成块，并标记 `has_code=true`。
- 每块保留 `page_from/page_to`，保证引用能定位到页码。

### 7.2 混合召回 + 融合

```
dense  : bge-m3 向量, top 30
sparse : BM25(jieba 分词 + 保留英文标识符/报错码), top 30
fusion : RRF(score = Σ 1/(60 + rank_i))  → top 15
rerank : bge-reranker-v2-m3 → top 5~6
```

**为什么必须要 BM25**：学生问的是 `ModuleNotFoundError: No module named 'flask'`、`CORS`、`Invalid bound statement` 这类**精确 token**，稠密向量对它们不敏感。这一条在答辩时是最容易被追问、也最容易讲清楚的技术点。

### 7.3 覆盖度判定（防幻觉的关键）

同时满足以下条件才进入生成，否则走拒答分支：

- rerank 归一化分 ≥ `MIN_SCORE`（初值 0.35，需在评测集上校准）
- 至少 1 个 chunk 与问题的关键词重合度 ≥ 阈值
- top1 chunk 的 `course` 与问题槽位一致（若问题能提取出课程）

拒答话术不是"我不知道"，而是：**说明知识库覆盖范围 → 给出 2 条替代路径（换问法 / 上传相关文档 / 提问教师）**，并把该问题记入"未覆盖问题池"，供教师端补充语料。这形成闭环，也是"数据飞轮"的素材。

## 8. 教学策略层设计（核心创新）

### 8.1 意图分流

LLM 结构化输出（JSON mode），四类：

| 意图 | 判定特征 | 输出形态 |
|---|---|---|
| `concept` | "什么是闭包""索引为什么失效" | 讲解 + 引用 + 1 道自测题 |
| `debug` | 附带报错/堆栈/截图 | 假设列表（按概率排序）+ 最小验证步骤 + 需补充的信息 |
| `request_solution` | "直接给我代码""帮我写完这个函数""作业答案" | **拒绝 + 三级提示阶梯** |
| `chitchat` | 与课程无关 | 简短回应 + 引导回课程 |

### 8.2 三级提示阶梯

| 级别 | 内容 | 解锁条件 |
|---|---|---|
| L1 定位 | 指出涉及的知识点章节 + 一句方向性提示，不给代码 | 默认 |
| L2 思路 | 步骤化思路 / 伪代码（**不含可运行实现**） | 学生提交自己的尝试（≥20 字或代码片段） |
| L3 骨架 | 函数签名 + `# TODO` 注释 + 边界条件清单 | 完成一个检查点问题（如"你认为这里应该用循环还是递归？"） |

状态存 `sessions.hint_level`；每级有冷却时间，防止刷级。**这一步是视频里最出彩的 60 秒**：同一个问题，直接问只给一句提示，学生写了尝试后才逐步展开。

### 8.3 泄露检测（输出侧守门）

规则优先，命中即触发降级重写：

1. 代码块 > 8 行且无 `TODO`/`pass` 占位
2. 出现完整函数体（`def ...:` 后含 `return` 且行数 ≥ 5）
3. 代码块占答案比例 > 60%
4. 命中"可直接复制运行""完整答案如下"等话术

降级策略：调用"改写为提示版"的 prompt，保留思路、删掉实现；同时写 `leak_events` 记录，教师端可复核（避免误杀不可见）。

### 8.4 引用强制

生成后校验：答案中每个 `[n]` 必须能在 `citations_json` 找到对应 chunk；找不到则删除该句或整段重写。前端把 `[n]` 渲染为可点击卡片，点击展开原文片段 + 文档名 + 页码。

## 9. 报错截图诊断链

```
上传图片 → VLM(或 OCR 兜底) 提取报错文本
   → 归一化(去 ANSI 色码/路径/时间戳, 提取异常类型+消息)
   → ① 指纹库匹配(精确 > 相似度)
   → ② 未命中则走 debug 意图 RAG
   → 输出: 可能原因(排序) + 每条的验证方法 + 需要学生补充的信息
```

**指纹库**（`error_patterns` 表，种子 20~30 条）是稳定性的关键：常见错误（`ModuleNotFoundError`、`IndentationError`、`TypeError: 'NoneType'`、`CORS`、`Cannot read properties of undefined`、SQL 连接串错误……）走确定性路径，回答质量稳定、延迟低，演示不容易翻车。

## 10. 评测设计（"能自证"）

评测集 `data/eval/eval_set.jsonl`，每条：

```json
{"id":"q001","question":"...","intent":"debug","course":"python",
 "gold_chunk_ids":["c1023","c1088"],"must_cite":true,
 "forbidden":"完整实现","expect_refusal":false}
```

指标：

| 指标 | 定义 | 目标 |
|---|---|---|
| Recall@5 | gold chunk 落在 top5 的比例 | ≥ 0.80 |
| MRR@10 | 首个正确 chunk 排名倒数均值 | ≥ 0.65 |
| 引用覆盖率 | 含断言的句子中带有效引用的比例 | ≥ 0.90 |
| 忠实度 | LLM 裁判 1–5 分（答案是否被引用内容支持） | ≥ 4.0 |
| **答案泄露率** | `request_solution` 类样本中产出完整实现的比例 | **≤ 10%** |
| 拒答正确率 | 无覆盖样本被正确拒答的比例 | ≥ 0.85 |
| 首 token 延迟 | P50 / P95 | < 2s / < 4s |

页面展示最近 N 次 run 的对比（折线 + 表格），并附 `git_sha`——**"我们的指标随提交在变好"** 比任何形容词都有说服力。

## 12. 部署

- **开发**：`scripts/dev.ps1` 同时起 `uvicorn --reload`（8000）与 `vite`（5173），前端代理 `/api` 到后端。
- **评审/生产**：`docker-compose.yml`（backend + 前端静态构建 + 可选 Qdrant 服务端 + nginx）。本机无 Docker，故文件先写好、在服务器上验证，README 里说明"两种运行方式"。
- **零依赖演示路径**：`python -m scripts.seed` 灌入样例语料 + `EMBED_PROVIDER=hash`，没有 API key 也能看到完整界面（答案质量受限，仅用于走查 UI）。

## 13. 主要风险与取舍

| 风险 | 影响 | 应对 |
|---|---|---|
| 策略层做不扎实（prompt 一绕就破） | 核心卖点崩塌 | 规则泄露检测兜底 + 评测集覆盖 10 种"绕法"变体（"我老师让我抄""我在做毕业设计"） |
| 语料质量差 | 检索命中率上不去 | 先做 20 篇高质量语料，宁少勿滥；坏的直接不进库 |
| 无 API key | M2 起阻塞 | 先确认 key；同时保证 hash 降级模式可跑通 |
| Python 3.13 兼容 | 装依赖踩坑 | 严格锁版本；torch 相关全部列为可选 |
| 泄露检测误杀 | 正常教学回答被降级 | 阈值可配 + 误杀记录可复核 + 评测里单独统计误杀率 |
| 视频录制翻车 | 演示效果打折 | 演示问题固定、语料固定、预演 3 次；关键片段录屏分段再剪 |
