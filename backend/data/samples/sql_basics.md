# 数据库与 SQL 基础排查笔记（示例课程资料）

> 本文件是项目自制的示例教学资料，用于演示知识库检索与引用。

## 一、NULL 不是空字符串

在 SQL 里 `NULL` 表示"未知"，它不等于 `0`，也不等于空字符串 `''`。

任何与 `NULL` 的比较（`= NULL`、`<> NULL`）结果都是"未知"，不会被 `WHERE` 选中。

正确写法是 `IS NULL` 与 `IS NOT NULL`。

在聚合函数里，`COUNT(*)` 统计所有行，而 `COUNT(column)` 会跳过该列为 `NULL` 的行，这是查询结果对不上的常见原因。

## 二、JOIN 的连接条件

`INNER JOIN` 只保留两边都能匹配上的行；`LEFT JOIN` 保留左表全部行，右表匹配不上时补 `NULL`。

写连接条件时要注意：

- 条件写在 `ON` 里与写在 `WHERE` 里，对 `LEFT JOIN` 的结果并不等价；
- 把右表的过滤条件写到 `WHERE`，会让 `LEFT JOIN` 退化成 `INNER JOIN`；
- 连接键的类型要一致，字符串与数字比较可能触发隐式转换，导致索引失效。

## 三、WHERE 与聚合的执行顺序

SQL 的逻辑执行顺序大致是：`FROM` → `JOIN` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY` → `LIMIT`。

由此可以得到两个结论：

- `WHERE` 在分组之前执行，所以不能直接对聚合函数的结果做过滤；
- 对聚合结果的过滤要写在 `HAVING` 里。

另外，`SELECT` 里定义的别名通常不能直接在 `WHERE` 中使用，因为 `WHERE` 执行得更早。

## 四、常见的字段与表名错误

报错信息里出现 "no such column" 或 "Unknown column" 时，先确认：

- 字段名是否拼错、是否多了空格；
- 表别名是否写错；
- 是否忘了给表起别名，却用了别名前缀；
- 字段是否在另一张表里，需要加表名前缀。

出现 "no such table" 时，确认数据库文件或连接串是否指向了正确的库，以及表是否已经创建。

## 五、排查顺序建议

1. 先单独执行最内层的子查询，确认它返回的数据形态；
2. 再逐步加上 `JOIN`，每加一步看行数变化；
3. 检查 `NULL` 相关的条件是否写成了 `= NULL`；
4. 检查过滤条件放在 `ON` 还是 `WHERE`；
5. 最后再优化索引与性能。
